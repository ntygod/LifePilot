## Web UI 主对话页 UX 评审（ChatView.vue）

> **模块编号**：Phase 5 — 模块 18 / 主对话页  
> **依赖模块**：Web UI 框架（模块 18）、知识库管理（模块 8）、Skill 系统（模块 10）、A2A/Trace（模块 2）、工作流编排（模块 15）  
> **最后更新**：2026-02-28

---

## 1. 模块定位与职责边界

### 1.1 模块定位
- **统一对话入口**：作为 Lifepilot 的主入口页面，承载用户与 Agent 的自然语言交互。
- **能力中枢可视化**：在对话上下文中，把“知识库 / Skill / MCP 工具 / 工作流 / 轨迹”等后端能力以合适粒度暴露出来。
- **开发与调试桥梁**：为 Skill / 工作流 / Agent 开发者提供轻量调试信息与跳转入口，连接到 Trace / 管理页。

### 1.2 职责边界

| 属于本模块 | 不属于本模块 |
|-----------|------------|
| 单/多会话 UI 与状态管理 | 知识库、Skill、工作流的核心执行逻辑 |
| 消息列表渲染、输入区交互 | Trace 详细可视化（由轨迹回放页负责） |
| 流式生成与中断控制 | YAML 配置编辑（Skill / Workflow 仍在文件层完成） |
| 基础的错误与状态反馈 | 高级监控与统计分析（由可观测性模块负责） |
| 与管理页之间的快捷跳转 | 系统级权限控制、审计日志 |

## 2. 当前信息架构概览

### 2.1 版式与区域划分
- **消息区域**
  - 垂直消息列表（`MessageList`），居中窄列展示。
  - 顶部为最近消息，向上滚动查看历史。
- **状态提示**
  - 全局错误条：显示最新错误信息，可关闭。
  - 流式状态条：在生成中时展示“停止生成”按钮。
- **输入区域**
  - 底部 `ChatInput`，支持发送文本消息。

> 当前实现偏向**“单会话 + 线性对话”**模型，未在 UI 中显式引入多会话和上下文切换概念。

### 2.2 关键对象与关系
- **Conversation（会话）**
  - 当前 UI 假定只有一个隐式当前会话，全部消息放在同一个 `chatStore.messages` 中。
- **Message（消息）**
  - 基本包含 `role`（用户/助手）和 `content`，后续会扩展到 `tool` / `system` / `workflow` 类型。
- **Context（上下文）**
  - 包括所用模型、选中的知识库集合、启用的 Skill / MCP 工具、可能触发的工作流。
  - 目前仅在后端与 Agent 引擎中存在，UI 对用户不透明。

## 3. 关键 UX 维度评审

### 3.1 会话模型与多会话体验

**现状**
- 仅支持单一隐式会话，无侧边会话列表、无命名、无重置。

**评审**
- 对于长期使用的 AI 助手，多会话是高频需求：
  - 用户需要按主题分会话（项目 A / 报告 B / 私人记录等）。
  - 需要快速在会话间切换，并识别当前上下文。
- 缺少多会话能力，会导致：
  - 所有内容挤在一个长对话中，后期检索和管理困难。
  - “清空”与“继续”边界模糊，用户难以判断模型记住了什么。

**建议**
- 引入**左侧会话列表栏**，支持：
  - 列表项：名称、最近时间、简短摘要。
  - 操作：新建、重命名、删除、置顶、清空当前会话。
- 清晰区分：
  - “开始新对话” = 新建会话。
  - “清空当前对话” = 删除当前会话的历史消息，但保留会话槽位。

---

### 3.2 消息展示与可读性

**现状**
- 使用居中窄列展示消息列表，整体样式尚简洁，但缺少：
  - 时间戳、发送状态等基础信息。
  - 对长消息的折叠与结构化。

**评审**
- 在“复杂任务 + 长对话”场景下，消息可读性要求远高于一般聊天应用：
  - 需要清晰标识“这条答案是什么时候给的”“当时用了哪些上下文”。
  - 需要快速跳转、折叠、复制关键部分（尤其代码、命令）。
- 当前实现处于**Demo 级展示**，不足以支撑长期密集使用。

**建议**
- 设计统一的 `MessageCard` 样式，支持：
  - 头部：头像/标识（User / Assistant / Tool）、时间、状态图标。
  - 内容：Markdown 渲染、代码块高亮、可折叠长内容。
  - 底部操作：复制、重新生成、基于此改写、查看来源（知识库 / 工具）。
- 对于工具调用、工作流执行等，使用专门的“工具卡片 / 时间线项”展示，而不是与普通文本混在一起。

---

### 3.3 输入区与任务发起体验

**现状**
- 单一输入框 + 发送，缺少快捷键提示、模板/示例、附件入口。

**评审**
- 主对话页不仅是“问答框”，更是各种任务的启动入口：
  - 启动工作流任务（例如：总结周报、生成 PR 说明）。
  - 触发高级 Skill（例如：调用外部数据源、执行自动化操作）。
  - 选择不同 Agent 形态（助手 / 分析 / 规划等）。
- 当前输入区对这些能力没有任何可见性，会导致“功能藏在系统里，用不起来”的问题。

**建议**
- 在输入区上方或内部增加：
  - 示例问题 / 常用任务 chips（可配置）。
  - 最近使用 Prompt 模板列表。
  - 文件上传 / 选文档作为临时上下文的入口。
  - 轻量设置：本会话的语气 / 风格预设选择。
- 显示清晰的快捷键提示：
  - `Enter` 发送、`Shift+Enter` 换行。

---

### 3.4 流式生成与中断控制

**现状**
- 在生成中时显示一行“停止生成”按钮，视觉权重较低，与具体消息无明显关联。

**评审**
- 在长回答、代码生成等场景，流式体验是用户感知“系统是否在工作”的关键：
  - 需要可见的打字机 / Skeleton 效果。
  - 需要清晰的“停止”“重新生成”控制。
- 当前实现容易出现：
  - 用户误以为系统卡住（缺少明显 loading）。
  - 不清楚停止生成后，是否还能基于未完成内容继续操作。

**建议**
- 把流式状态绑定到**具体正在生成的消息卡片**上：
  - 消息内展示光标闪烁 / Skeleton。
  - 在该卡片右上角提供“停止生成 / 重新生成”按钮。
- 保留全局层的“生成中”状态（如顶部细进度条或状态条），用于多消息并发等复杂场景。

---

### 3.5 空状态与错误反馈

**现状**
- 空状态仅显示“开始新对话”一行文本。
- 错误通过全局一条 `error` 文本展示，缺少分类与操作。

**评审**
- 主对话页的空状态是“产品自我介绍”的关键位置，应承担引导职责：
  - 告诉用户“这里能做什么”“先试试这些问题”。
  - 尤其要露出知识库 / Skill / 工作流等差异化能力。
- 错误体验直接影响用户对系统可靠性的感知：
  - 模糊的错误文本 + 缺少重试，是常见的流失点。

**建议**
- 空状态：
  - 展示 3–5 个示例问题，覆盖典型场景（知识库问答、Skill 调用、工作流自动化）。
  - 简要说明：对话如何与“管理页里配置的东西”协同工作。
- 错误状态：
  - 区分网络错误 / 限流 / 工具调用失败 / 系统异常，给出不同文案与建议。
  - 每条失败的消息卡片上显示“重试”按钮，以及“查看执行轨迹”的入口。

---

### 3.6 与知识库 / Skill / 轨迹 / 工作流的联动

**现状**
- 管理页已实现，但主对话页中几乎没有与这些模块的显式联动。

**评审**
- 从用户视角看，“对话页 + 四个管理页”是一体的：
  - 管理页负责配置“能力”，对话页负责“使用能力”。
  - 但当前信息架构中，这两者之间的桥梁缺失。

**建议**
- 顶部或消息区域增加“上下文指示条”：
  - 当前使用的模型 / 知识库集合 / 已启用的关键 Skill。
  - 提供跳转到对应管理页的轻量链接。
- 在消息卡片中：
  - 当答案引用知识库内容时，显示“来自知识库 X / 文档 Y”标签，可点击跳转。
  - 当调用工具 / 工作流时，展示“工具调用卡片”，可跳到 Trace 详情或工作流执行记录。

---

### 3.7 调试与高级用户视角

**现状**
- 调试能力主要在轨迹回放页实现，主对话页没有轻量调试视图。

**评审**
- 面向内部开发者 / 高级用户：
  - 他们希望在“不离开对话页”的前提下快速看到本轮执行概要。
  - 全量 Trace 视图太重，不适合每次切过去看。

**建议**
- 在主对话页右侧或底部，提供一个可折叠的“调试抽屉”：
  - 显示最近一轮对话的：
    - 整合后的 Prompt（系统 + 用户 + 工具上下文摘要）。
    - 使用的模型 / 参数。
    - 工具调用列表、耗时与基本结果摘要。
    - Token 统计（输入 / 输出 / 总计）。
  - 保持与 Trace 页的数据来源一致，但只呈现摘要。
- 在抽屉中提供“查看完整轨迹”按钮，跳转到 Trace 页对应条目。

## 4. 典型用户路径分析（示例）

### 4.1 新用户第一次使用
1. 打开主对话页，看到空状态说明与示例问题。
2. 点击一个“示例问题”（如“帮我总结本周知识库中的新文档变化”）。
3. 看到回答中标注“来自知识库 X / 文档 Y”，并能一键查看文档详情。
4. 对系统有清晰认知：不仅会聊天，还能用自己文档 / 工具 / 工作流做事。

### 4.2 开发者调试新 Skill / 工作流
1. 在管理页创建 / 启用新的 Skill / 工作流。
2. 回到主对话页，通过输入区模板或示例问题触发该能力。
3. 在对话中看到：
   - 工具/工作流调用卡片（状态、耗时、核心输出）。
   - 调试抽屉中显示本轮调用详情与 Token 情况。
4. 如遇错误，可一键跳转到 Trace 详情继续排查。

## 5. 关键设计决策建议

| # | 决策 | 理由 |
|---|------|------|
| 1 | 主对话页采用“中间消息 + 左侧会话列表 + 可选右侧调试抽屉”的三栏布局 | 平衡日常使用（中间）与会话管理（左侧）、调试（右侧）需求 |
| 2 | 工具调用 / 工作流执行在消息流中以“工具卡片”形式展示 | 避免被当作普通文本掩埋，提升可解释性 |
| 3 | 调试信息在主对话页只展示摘要，详细信息交给 Trace 页 | 控制主对话页复杂度，保持日常使用简洁 |
| 4 | 知识库 / Skill / 工作流管理始终通过独立页面完成 | 避免主对话页承载过重配置逻辑，保持清晰分工 |
| 5 | 优先实现多会话基础能力，再拓展搜索、导出等进阶功能 | 保障基础管理能力后，再优化效率工具 |

## 6. 与其他 Web UI 模块的协同

### 6.1 与管理页（知识库 / Skill / 轨迹 / 工作流）
- 管理页负责：配置、查看、控制。
- 主对话页负责：使用、体验、反馈。
- 协同方式：
  - 管理页中提供“在对话中试用”入口（跳转到主对话页并预填测试 Prompt）。
  - 主对话页中提供“查看详情 / 管理”入口（跳回管理页具体对象）。

### 6.2 与 Web UI 框架（路由 / 导航）
- 在全局导航中突出主对话页入口，保证一跳可达。
- 在多会话模式下，路由中应包含会话 ID，支持刷新 / 分享 URL。

## 7. 后续迭代建议（路线图视角）

### 7.1 第一阶段（基础体验）
- 消息卡片化：时间戳、角色标识、发送状态、基础 Markdown/代码渲染。
- 空状态与错误体验重做：示例问题、错误分类与重试。
- 流式状态显著化：绑定到具体消息卡片、全局状态条。

### 7.2 第二阶段（能力可视化与多会话）
- 多会话列表：新建 / 删除 / 重命名 / 清空。
- 上下文指示条：当前模型 / 知识库 / Skill 状态。
- 工具调用与知识库引用的可视化，以及跳转到管理页 / Trace 页的入口。

### 7.3 第三阶段（调试与高级功能）
- 调试抽屉：Prompt 摘要、工具调用列表、Token 统计。
- 对话搜索 / 过滤、对话导出 / 分享。
- 个性化设置（布局、主题、密度）与可访问性增强。

> 本文档聚焦于 UX 结构与交互层面的评审，不约束具体视觉风格与组件库实现，可在后续设计阶段结合现有 UI 体系细化。
