## 项目经历

### 知微（ZhiWei）— AI Agent 个人助手（独立项目）

**项目周期**：2025.xx - 至今（持续迭代中）
**项目地址**：GitHub [地址]
**技术栈**：Java 22 / Spring Boot 3.5 / Spring AI 1.1 / SQLite + sqlite-vec / Flyway / Vue 3 / Vite / Pinia / Docker
**项目规模**：后端 24 个模块、前端 30+ 页面视图、40+ Flyway 迁移脚本

**项目描述**：
知微是一个本地运行的 AI Agent 助手，区别于普通 ChatBot 的一问一答模式，它是一个完整的 Agent 系统——能自主调用工具完成任务、具备跨会话的长期记忆、能基于用户行为模式主动提供建议。所有数据存储在本地 SQLite，单 JAR 部署零外部依赖，面向个人用户提供隐私友好的智能助手体验。

**核心技术亮点**：

#### 1. ReAct Agent 推理引擎（核心模块，面试重点）

- 自研 ReactAgentLoop 控制循环，实现 ReAct 推理范式（Thought → ToolCall → Observation → Answer），每轮推理产生不可变状态快照（AgentState record）
- 手动实现 Tool Calling 机制（关闭 Spring AI 内置 internalToolExecutionEnabled），完全掌控工具执行流程，在工具调用前后插入护栏检查（GuardrailAdvisor）、审计日志（AuditMiddleware）、敏感数据脱敏（DataRedactor）等横切逻辑
- 使用 sealed interface（ReactStep）定义 6 种步骤类型 + switch 表达式穷举匹配，保证类型安全
- 实现 5 种 Agent 挂起/恢复场景（WorkflowWait / UserConfirmation / RemoteDelegation / ScheduledWakeup / ExternalDataWait），Agent 状态持久化到 SQLite，支持跨进程恢复
- ContextAssembler 上下文组装器：动态从四层记忆系统检索相关记忆，结合对话历史压缩，按 Token 预算（可配置比例）分配各部分上下文窗口，避免超出 LLM 上下文限制

**设计决策**：选择手动 Tool Calling 而非框架内置方案，是因为 Agent 场景需要在工具执行前做风险评估（四级风险分级）、执行后做轨迹记录，框架内置的自动执行无法插入这些关键环节。

#### 2. 四层认知记忆系统（最有区分度的模块）

- 参考认知科学的记忆分层模型，设计 L1~L4 四层记忆架构：
  - L1 工作记忆（WorkingMemory）：当前会话的临时上下文，支持 flush 时自动压缩（CompressionService 调用 LLM 提炼摘要）
  - L2 情景记忆（EpisodicMemory）：完整对话记录 + 注入记录，支持按时间范围和相关性检索
  - L3 语义记忆（SemanticMemory）：时序知识图谱，包含 TemporalEntity（实体 + 重要性评分 + 访问计数）和 TemporalRelation（关系 + 时间维度），支持时间旅行查询
  - L4 程序记忆（ProceduralMemory）：ProcedureTemplate（技能模式模板）+ PreferenceRule（用户偏好规则），从历史交互中自动提炼
- 记忆巩固管线（ConsolidationPipeline）：定时 + 空闲触发，将短期记忆（L2 情景）提炼为长期记忆（L3 语义 / L4 程序），包含情景→语义巩固器和情景→程序巩固器两条路径
- 混合检索引擎（HybridRetriever）：三路并行检索（sqlite-vec 向量相似度 + FTS5 全文匹配 + 时序知识图谱遍历），fusedScore 融合排序算法加权合并结果，预算感知截断确保不超出 Token 限制
- 查询改写（QueryRewriter）：对用户原始查询进行语义扩展和改写，提升检索召回率
- MaRS 认知遗忘策略：基于时间衰减 + 访问频率 + 重要性评分的综合遗忘算法，过期记忆自动归档而非删除

**设计决策**：选择 SQLite + sqlite-vec 而非 Milvus/Pinecone 等专用向量数据库，是因为项目定位为本地优先的单用户应用，SQLite 零外部依赖 + 单文件存储的特性完美匹配部署约束，同时 FTS5 全文索引和 sqlite-vec 向量扩展已能满足个人级别的检索性能需求。

#### 3. 多 LLM 智能路由与容错

- LlmRouter 实现三级路由策略：优先按 scene（场景）匹配 → 其次按 modelName（指定模型）→ 最后按 capability（能力要求，如多模态支持）匹配
- ProviderRegistry 运行时动态管理 LLM 服务商（DeepSeek / OpenAI / Anthropic Claude / 通义千问 / Ollama），支持通过 Web UI 可视化配置，无需重启
- CircuitBreaker 熔断器：实现 Closed → Open → HalfOpen 三态转换，失败率超阈值自动熔断，半开状态探测恢复；配合 ExponentialBackoff 指数退避（初始 500ms，倍数 2.0，上限 5s）实现故障转移到备选 Provider
- SemanticCache 语义缓存：基于 scene + responseFormatKey + prompt 三维匹配，对相似请求直接返回缓存结果，减少 LLM 调用成本和延迟
- SSE 流式响应：后端通过 Flux&lt;ServerSentEvent&gt; 实时推送 Token 流，前端逐字渲染，支持工具调用中间状态的实时展示

#### 4. 三层工具架构与 Skill 自扩展

- 设计 ToolContract sealed interface 统一工具契约，三层优先级：BuiltinTool（Java 原生实现，最高优先级）→ SkillTool（YAML 声明式定义，中优先级）→ McpTool（MCP 外部工具，最低优先级）
- 7 大元能力维度分类（ToolCategory）：感知 / 行动 / 认知 / 存储 / 交互 / 自省 / 扩展
- DynamicToolRegistry 运行时工具注册表：支持热加载，YAML Skill 修改后即时生效，无需重启
- Skill 自扩展机制：SkillGenerator 运行时自动检测能力缺口（用户请求无匹配工具时触发），调用 LLM 生成 YAML Skill 定义，经过三阶段验证管线（FormatValidator → SecurityValidator → SandboxValidator）后自动注册
- 内置 Skill：待办管理（TodoSkillProvider）/ 日程管理（ScheduleSkillProvider）/ 习惯追踪（HabitSkillProvider）/ 定时任务（ScheduledTaskSkillProvider）/ 通用数据存储
- Skill 验证管线确保安全性：格式校验 → 安全扫描（检测危险操作）→ 沙箱试运行

**设计决策**：三层架构的设计动机是平衡「开发效率」和「扩展性」——核心高频工具用 Java 原生实现保证性能，业务工具用 YAML 声明式降低开发门槛，外部生态通过 MCP 协议无缝接入。

#### 5. 知识库 RAG 管线

- 多格式文档摄入：集成 PDFBox（PDF）、Apache POI（Word）、Apache Tika（格式检测），支持 PDF / Word / Markdown / TXT 四种格式
- 多分块策略：固定大小分块（可配置 chunk size + overlap）、语义分块（按段落语义边界切分）、标题分块（按文档标题层级切分）
- 混合检索：向量检索（sqlite-vec 余弦相似度）+ FTS5 全文检索 + 知识图谱遍历三路并行，融合排序后返回
- 可选 LLM Reranker 精排：对初检结果调用 LLM 进行相关性重排序，提升检索精度
- 多知识库实例管理：支持创建多个独立知识库，各自独立的文档集和检索空间

#### 6. Gateway 中间件管道与多渠道适配

- 6 层可插拔中间件管道，按优先级顺序执行：Auth（100）→ RateLimit（200）→ Security（300）→ Router（400）→ Execution（500）→ Audit（600）
- SecurityMiddleware 安全中间件：PromptInjectionDetector（Prompt 注入检测）+ SensitiveDataDetector（敏感数据检测）+ TrustScoreCalculator（信任评分计算）
- AuditMiddleware 审计中间件：DataRedactor 自动脱敏（6 条内置规则：API 密钥 / 手机号 / 身份证 / 银行卡 / 邮箱 / IP）+ 审计日志持久化
- ChannelAdapter 多渠道适配器：Web / CLI / 企业微信 / 钉钉 / 飞书，统一消息模型屏蔽渠道差异

#### 7. 护栏与安全体系

- GuardrailEngine 护栏引擎：5 种策略类型（ToolRiskPolicy / BudgetLimitPolicy / ContentSafetyPolicy / RateLimitPolicy / DataRedactionPolicy）
- GuardrailResult 三态决策模型：Passed（放行）/ Blocked（拦截）/ NeedsConfirmation（需用户确认）
- RiskLevel 四级风险分级：LOW（自动执行）→ MEDIUM（自动+审计）→ HIGH（用户确认）→ CRITICAL（确认+二次验证），每个工具在注册时声明风险等级
- 代码执行沙箱：Process / Docker 双模式，CodeValidator 在执行前预检危险操作（文件删除、网络访问、系统命令等）

#### 8. 可观测性与评估

- TraceRecorder 完整追踪：记录每次 Agent 执行的完整轨迹，包含 LlmCallStep（LLM 调用详情）/ ToolCallStep（工具调用详情）/ GuardrailStep（护栏检查详情）三种步骤类型
- 每个决策可追溯和回放，支持通过 Web UI 查看完整推理链路
- Agentic Evals 评估框架：YAML 声明式评估场景定义，五维规则评估（正确性 / 完整性 / 安全性 / 效率 / 格式）+ LLM-as-a-Judge 评分，集成 JUnit 5 可作为 CI 回归测试运行

#### 9. 其他亮点模块

- **多 Agent 协作**：AgentRegistry 注册管理 + HandoffTool 委托工具模式，SubAgent 拥有独立 Token 预算和上下文，预设写作 / 分析 / 调研三个专家 Agent
- **工作流引擎**：YAML 声明式工作流定义，支持 manual / cron / event 三种触发器，工作流状态持久化到 SQLite，支持崩溃后自动恢复
- **统一通知系统**：NotificationService 统一接口，Urgency 路由（HIGH/MEDIUM 实时多渠道广播，LOW 入队被动队列定时推送），富媒体支持（文本 / Markdown / 交互式卡片），被动队列 SQLite 持久化
- **MCP 协议支持**：McpServerRegistry 服务器发现 + 客户端管理，McpServerDiscovery 自动发现，McpTool 作为 ToolContract 最低优先级层无缝接入外部工具生态
- **A2A 协议**：实现 Google A2A（Agent-to-Agent）协议的 Client/Server 端，Agent Card 能力声明，支持跨系统 Agent 互操作
- **外部数据源同步**：CalDAV / Todoist / 滴答清单 / Obsidian 四个连接器，冲突解决策略（Last-Write-Wins / 用户确认）
- **通用数据存储**：Schema-Free JSON 文档持久化，三种集合类型（Document / Note / Metric），FTS5 全文搜索 + 时序聚合分析，7 个 Agent 工具支持 CRUD + 聚合查询

## 面试常见追问准备

以下是面试官可能深入追问的方向，建议提前准备好回答：

1. **为什么手动实现 Tool Calling？** → 需要在工具执行前后插入护栏检查、审计日志、脱敏等横切逻辑，框架内置的自动执行无法满足
2. **记忆系统的混合检索怎么做融合排序？** → fusedScore 加权算法，向量/全文/时序三路各有权重，预算感知截断
3. **熔断器的三态转换条件？** → 失败率超阈值 Closed→Open，超时后 Open→HalfOpen，探测成功 HalfOpen→Closed
4. **Skill 自扩展怎么保证安全？** → 三阶段验证管线：格式校验 → 安全扫描 → 沙箱试运行
5. **为什么选 SQLite 不选 PostgreSQL？** → 本地优先单用户场景，零外部依赖，单文件存储便于备份迁移
6. **Agent 挂起/恢复怎么实现？** → 状态序列化到 SQLite，5 种挂起原因对应不同恢复触发条件
7. **Token 预算怎么分配？** → 可配置比例，系统 Prompt / 记忆 / 对话历史 / 工具结果各占一定比例，动态调整
8. **项目中遇到的最大技术挑战？** → 建议准备 1-2 个具体案例（如记忆检索精度优化、LLM 流式响应中断恢复等）
