# 主动智能引擎演进设计

> 日期: 2026-04-13  
> 状态: 设计通过，待实施

## 1. 目标与愿景

**北极星**：贾维斯 — 全场景感知、主动行动、有人格、越来越懂用户。让知微区别于其他 AI 助手，从"被动应答"进化为"主动智能伙伴"。

**核心差距**：现有引擎名为 `ProactiveReminderService`，本质是一个提醒器——信号采集、打分、决策管线成熟，但唯一输出是"弹一条提醒"。要实现贾维斯级体验，需要将其泛化为**主动智能层**，支持多种主动行为。

## 2. 设计约束

| 约束 | 决定 |
|------|------|
| 自主度 | A(通知) → B(建议) → C(代行) 渐进，每种行为独立开关，用户主动同意升级 |
| 信号源优先级 | 对话深挖 > 剪贴板 > 外部数据 > 屏幕感知 > 提取日程 |
| LLM 资源策略 | 需求检测层轻量（规则），LLM 仅用于关键决策和内容生成 |
| 日历集成 | 不对接外部日历 App（国内用户习惯弱），改为从对话中提取轻量日程 |
| 通讯消息 | 企微/飞书/钉钉 Bot 回调的用户消息视为对话来源，不尝试获取用户其他群/对话 |

## 3. 整体架构（七层）

```
信号源（对话记忆 / 剪贴板 / 外部数据 / 屏幕感知 / 提取日程）
  │
  ▼
① 统一信号采集 ─── SignalCollector → ContextPacket
  │
  ▼
② 需求检测（轻量三级过滤，不调 LLM）
  │  SILENT → 结束（~80%）
  │  FAST   → 缓存上下文轻量响应（~15%）
  │  FULL   → 完整推理（~5%）
  │
  ▼
③ 行为插件（各自检测候选 + 精细推理 + 执行）
  │
  ▼
④ 意图记忆 ──── 持久目标 + 触发条件，每次心跳检查
  │
  ▼
⑤ 统一决策门控 ─ 跨行为去重 / 限流 / 自主度检查 / 用户状态
  │
  ▼
⑥ 四级投递阶梯 ─ 静默 / 排队 / 通知 / 打断
  │
  ▼
⑦ 反馈闭环 ──── 行为反馈 → 偏好学习 → 策略调优 → 自主度升降
                  回写到 ②阈值 / ③权重 / ⑤参数
```

## 4. 需求检测层（② 详细设计）

三级过滤，将 LLM 调用成本从 100% 降至约 5%：

**第一关：变化量检查（纯规则，零成本）**
- 对比上次心跳的 ContextPacket：记忆层有更新？外部数据到达？时间窗口触发？意图触发条件满足？
- 无变化 → SILENT，记录心跳日志，休眠
- 预估 80% 心跳到此结束

**第二关：快速打分（复用现有打分模型，零 LLM 成本）**
- 对变化信号跑现有 `ReminderScoringModel` 公式（30% 证据 + 25% 时机 + 20% 紧迫 + 15% 适配 + 10% 可行）
- 每个行为插件的 `detect()` 方法快速报告候选 + 粗略分数
- 最高分 < 0.4 → FAST，用缓存上下文生成轻量响应或排队
- 预估 15% 心跳到此

**第三关：完整 LLM 推理（仅约 5% 心跳）**
- 携带完整上下文调用 LLM
- 生成思维链（为什么现在要主动、要做什么）
- 输出：主动分数(1-5) + 动作类型 + 生成内容
- 思维链保存到决策日志，保证可解释性

**事件触发的迷你心跳**：剪贴板变化、屏幕切换等实时信号不等 30 分钟心跳，直接触发一次从第一关开始的快速检查，同样走三级过滤。

## 5. 行为插件系统（③ 详细设计）

### 5.1 插件接口

每个插件实现 3 个方法：

```java
interface ProactiveBehavior {
    // 快速检测：有没有候选？返回粗略分数（第二关用）
    List<Candidate> detect(ContextPacket ctx);

    // 精细推理：生成具体内容（第三关 FULL 时才调 LLM）
    ProactiveAction reason(Candidate candidate, ContextPacket ctx);

    // 执行动作（自主度为 C "代行" 时才用）
    ExecutionResult execute(ProactiveAction action);
}
```

### 5.2 七个行为插件

| 插件 | detect | reason | execute |
|------|--------|--------|---------|
| ⏰ 提醒 | 现有 5 类候选检测器迁入 | 现有 LLM 文案生成 | — |
| 📚 信息补充 | 用户高频话题 + 知识库新内容 | LLM 判断相关性并生成摘要 | 自动加入知识库（C 级） |
| 🎯 情境准备 | 提取日程中即将到来的事件 | LLM 决定准备内容 | 自动汇总对话/整理资料（C 级） |
| 💡 洞察推送 | 行为模式变化、趋势信号 | LLM 生成可解释洞察 | — |
| 🤖 任务代行 | 意图记忆中触发条件满足 | LLM 规划执行步骤 | 调工具/工作流/发消息（C 级） |
| ❓ 主动追问 | 对话中未完成话题/模糊意图 | LLM 生成自然追问 | — |
| 📊 日报周报 | 时间触发（每天/每周固定时段） | LLM 汇总活动/进展/待办 | 自动生成并推送（C 级） |

### 5.3 重构策略

- 现有 `ProactiveReminderService` 的 5 类候选检测器、打分模型、文案生成 → 迁入"提醒"插件
- LinUCB 赌博机、反馈仓库、策略调优 → 上提到框架层，所有插件共享
- 不丢失任何已有能力

### 5.4 心跳中的插件生命周期

```java
ContextPacket ctx = signalCollector.collect();

// 第一关: 变化量检查
if (!ctx.hasChangeSince(lastHeartbeat)) return SILENT;

// 第二关: 每个插件快速检测候选
List<Candidate> all = plugins.stream()
    .flatMap(p -> p.detect(ctx)).toList();
if (all.isEmpty() || maxScore(all) < 0.4) return FAST;

// 第三关: 高分候选进入精细推理
List<ProactiveAction> actions = topCandidates(all)
    .map(c -> c.behavior().reason(c, ctx)).toList();

// 统一决策门控 → 投递
decisionGate.evaluate(actions) → deliveryEngine.deliver();
```

## 6. 意图记忆（④ 详细设计）

让知微从"即时反应"变成"持续关注"的关键能力。

### 6.1 数据模型

```java
record Intent(
    String id,
    String userId,
    String goal,             // "买耳机"
    String triggerCondition, // 结构化条件 或 自然语言
    String sourceSessionId,  // 从哪次对话提取的
    IntentStatus status,     // ACTIVE / TRIGGERED / FULFILLED / EXPIRED
    LocalDateTime createdAt,
    LocalDateTime expiresAt, // 自动过期，防止永远占着
    int checkCount           // 已检查次数，用于衰减
)
```

### 6.2 意图来源

- **对话提取**：从 L2 情景记忆中识别"我想..."、"帮我盯着..."、"等...的时候告诉我"
- **用户显式创建**：对话中直接对知微说"帮我关注 XX"
- **行为插件产出**：任务代行插件执行后产生后续意图

### 6.3 生命周期

提取 → 存储（带触发条件 + 过期时间）→ 每次心跳检查 → 条件满足时触发对应行为插件 → 用户反馈/自动过期 → 完成

## 7. 统一决策门控（⑤ 详细设计）

多个插件可能同时产出候选动作。门控是防过度打扰的最后防线。

### 7.1 检查维度

**硬边界（一票否决）**：
- 安静时段（23:00-08:00）
- 同话题冷却期未过
- 每日上限已达
- 用户在全屏/专注模式

**软约束（降级处理）**：
- 已有一条通知未读 → 排队
- 用户刚拒绝过上一条 → 降级为静默
- 多个候选并列 → 只推最高分的
- 信任度不够 → 降一级自主度

**自主度检查**：
- A 通知型 → 只允许通知/排队
- B 建议型 → 允许通知 + 带方案
- C 代行型 → 允许执行，完成后告知

### 7.2 投递级别

| 级别 | 分数区间 | 行为 |
|------|---------|------|
| 静默 | < 0.3 | 仅记录到决策日志 |
| 排队 | 0.3–0.5 | 存储，下次用户主动对话时展示 |
| 通知 | 0.5–0.7 | 浮窗气泡 / 桌面通知 |
| 打断 | ≥ 0.7 | 主动消息 / 直接发到渠道 |

### 7.3 复用现有能力

- 硬边界检查 → 现有 `ReminderDecisionEngine` 逻辑上提
- LinUCB 赌博机 → 从提醒专用变成全局共享
- 反馈仓库 → 从提醒专用扩展为全行为类型

## 8. 自主度阶梯

不是全局一刀切，每种行为独立设级。

| 行为 | A 通知 | B 建议 | C 代行 | 默认 |
|------|--------|--------|--------|------|
| 提醒 | 告诉你有这事 | — | — | A |
| 信息补充 | 推送相关资料 | 附带"要深入了解吗" | 自动加到知识库 | A |
| 情境准备 | 提醒你要准备 | 准备好草稿等你确认 | 直接准备好放那 | B |
| 洞察推送 | 推送洞察 | — | — | A |
| 任务代行 | 告诉你可以做 | 展示执行计划等确认 | 直接执行再告知 | B |
| 主动追问 | 在对话中自然追问 | — | — | A |
| 日报周报 | 推送给你看 | 草稿等你编辑后发 | 自动生成并发送 | B |

**信任升级机制**：某行为连续 N 次正反馈 → 系统建议升级自主度 → **用户确认后才生效**，永远不会自动升级。

## 9. 演进路线图

### Phase 1 — 框架重构（基础）

- 抽象 `ProactiveEngine` 框架 + `ProactiveBehavior` 接口
- 实现三级需求检测（SILENT/FAST/FULL）
- 迁移现有提醒为第一个行为插件
- 统一决策门控 + 四级投递阶梯
- 新增"排队"投递渠道（下次对话展示）

**交付标准**：现有提醒功能不退化，LLM 调用量显著下降。

### Phase 2 — 深度感知（感知力）

- 意图记忆：从对话中提取持久目标 + 心跳检查触发条件
- 对话深度挖掘：升级信号采集器，提取情绪、关注点、未完成话题
- 上线"主动追问"和"洞察推送"两个插件
- 剪贴板意图检测从前端独立逻辑迁入引擎框架

**交付标准**：知微能追踪用户说过的目标，在合适时机主动追问或推送洞察。

### Phase 3 — 主动行动（行动力）

- 上线"信息补充"、"情境准备"、"日报周报"三个插件
- 自主度阶梯：A/B/C 级别 + 每行为独立开关
- "任务代行"插件：对接工作流引擎和工具系统
- 信任升级机制：连续正反馈 → 建议升级自主度

**交付标准**：知微不只能提醒，还能准备、汇总、代行，用户可控深浅。

### Phase 4 — 全域感知（贾维斯）

- 屏幕/应用感知：Tauri 桌面端集成（当前应用、焦点状态、AFK 检测）
- 对话提取轻量日程（替代外部日历）
- 跨行为智能：多个插件共享上下文，形成连贯的主动体验
- 五维偏好模型：从行为反馈中自动学习时间/领域/风格偏好

**交付标准**：知微像贾维斯一样持续感知环境，多维度主动服务。

## 10. 业界研究参考

本设计参考了以下业界研究和开源实践（详见 `docs/research/proactive-ai-research-report.md`）：

- **三级需求检测**：PASK (arXiv 2604.08000) 的 SILENT/FAST/FULL 三令牌架构
- **主动分数**：ContextAgent (NeurIPS 2025) 的 1-5 评分 + 阈值机制
- **五维偏好模型**：arXiv 2602.04000 的行为反馈优于自述偏好（61.3% vs 57.7%）
- **任务边界时机**：开发者实地研究（52% 接受率 vs 31%）
- **意图记忆**：Long-term Task-Oriented Agent (arXiv 2601.09382) 的持久意图模式
- **自主度阶梯**：CHI 2024 Workshop 的四级自主度 + 信任校准
- **心跳模式**：OpenClaw (68k stars) 的 Wake→Observe→Reason→Act→Sleep 架构
