# 记忆模块端到端测试计划

> 通过真实流式对话接口（POST /api/chat/messages/stream）验证记忆模块的完整数据流转。
> 覆盖 L0→L1→L2→L3→L3.5→L4 全链路 + 项目隔离 + 生命周期 + 巩固 + 遗忘 + 质量治理。

---

## 测试环境

- 应用：localhost:8080
- Embedding：localhost:8081（BAAI/bge-m3, 1024 维）
- Reranker：localhost:8082
- LLM：DeepSeek（生成 + AUDN 提取）
- 数据库：本地 SQLite（含已有测试数据）

---

## 一、写入链路（L0 → L3）

### 1.1 AUDN 自动提取

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 教学 | "我叫李华，30岁，在北京做架构师，养了一只橘猫叫咪咪" | 系统确认记住 |
| 验证提取类型 | 用 memory.search 搜索 "李华" | 应返回 PERSON 类型实体 |
| 验证质量字段 | 检查返回实体的 trust_level | 应为 EXPLICIT（用户直接陈述） |
| 验证 provenance | 检查实体来源 | 应关联到当前 session/turn |

### 1.2 提取边界（不该学的不学）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 计算请求 | "帮我算 127*33" | 不应产生长期记忆实体 |
| 系统指令 | "用中文回答我" | 不应作为用户事实提取 |
| 工具结果 | 让系统调用工具后，检查工具返回值是否被当作用户事实 | 工具结果不应直接进入 L3 个人记忆 |

### 1.3 候选流水线与质量门控

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 低置信提取 | "我可能喜欢爬山吧"（模糊表述） | 应标记为 CHAT_INFERRED，trust_score 较低 |
| 明确陈述 | "我确定喜欢游泳" | 应标记为 USER_EXPLICIT，trust_score 高 |
| 对比注入 | 新会话问 "我喜欢什么运动" | EXPLICIT 的"游泳"应优先出现，INFERRED 的"爬山"可能不注入或标注"推断" |

## 二、版本化与冲突（L3 核心）

### 2.1 知识更新（VersionMerger）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 初始值 | 已有 "住在北京" | — |
| 更新 | "我搬到上海了" | 系统确认更新，显示旧→新 |
| 跨会话验证 | 新会话问 "我住哪" | 回答"上海"，不回答"北京" |
| 搜索验证 | memory.search "居住地" | 应只返回"上海"版本（旧版本 is_current=0） |

### 2.2 实体合并（ConflictDetector）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 首次提及 | "我的猫叫咪咪" | 创建实体 |
| 补充信息 | "咪咪今年2岁，喜欢晒太阳" | 合并到同一实体（版本号+1），不创建新实体 |
| 验证合并 | memory.search "咪咪" | 单条实体，包含品种+年龄+爱好 |

### 2.3 语义冲突检测（三级）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 精确匹配 | 再次说 "我的猫叫咪咪，是只英短" | 精确匹配命中已有实体，合并品种信息 |
| 语义匹配 | "我家的猫咪特别粘人" | 语义匹配到"咪咪"实体（向量相似度） |
| 不同实体 | "我朋友的猫叫花花" | 不应合并到"咪咪"，应创建新实体 |

## 三、消费链路（L3.5 热记忆 + L2 冷召回）

### 3.1 热记忆自动注入（HotMemoryDigest）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 直接提问 | 新会话："我叫什么？" | 直接回答，不调用 memory.search 工具 |
| 验证来源 | 检查 SSE 流中的 reasoning 事件 | 应提到 "hot memory" 或 "memory_context" |
| 预算控制 | 写入大量实体后问 "你记得我什么" | 回答应精简（热记忆有 token 预算限制） |

### 3.2 冷召回工具

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| memory.search | "搜索和宠物相关的记忆" | 返回实体列表，含 score breakdown |
| memory.recall | "回忆我们之前聊猫的对话" | 返回历史对话片段（L2 FTS 命中） |
| 语义搜索 | "搜索我的职业信息" | 向量路径命中"架构师"实体 |
| 不相关搜索 | "搜索量子计算" | 返回空或极低分结果 |

### 3.3 检索质量字段

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| scoreBreakdown | memory.search 返回结果 | 应包含 vector/fts/graph 各路分数 |
| 生命周期标注 | 搜索已完成的目标 | 应标注 isHistorical=true |
| trust 过滤 | UNVERIFIED 实体 | 不应出现在搜索结果中 |

---

## 四、生命周期管理

### 4.1 目标完成（ACTIVE → COMPLETED）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 设定目标 | "我的目标是考 AWS 认证" | 创建 GOAL 实体，lifecycle=ACTIVE |
| 完成目标 | "我已经考过 AWS 认证了" | 系统应将实体标记为 COMPLETED |
| 验证状态 | "我还有什么未完成的目标" | 不再列出 AWS（或标注已完成） |
| 搜索行为 | memory.search "AWS" | 仍可搜到，但标注 isHistorical |

### 4.2 记忆取消（cancel）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 否定记忆 | "你记错了，我不养猫" | 系统应取消/归档"咪咪"实体 |
| 验证取消 | "我养了什么宠物" | 不再提到咪咪 |
| 搜索行为 | memory.search "咪咪" | 不应返回（CANCELLED 不可召回） |

### 4.3 记忆替代（supersede）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 偏好变更 | "我不用 VS Code 了，改用 Cursor" | 旧实体 SUPERSEDED，新实体 ACTIVE |
| 验证 | "我用什么编辑器" | 回答 Cursor |
| 血缘 | 新实体应有 succeeded_by 指向关系 | — |

## 五、L4 程序记忆

### 5.1 偏好规则同步

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 建立偏好 | "我喜欢代码用4空格缩进，不用 tab" | L3 PREFERENCE 实体创建 |
| 巩固后 | 触发 consolidation 或等待 cron | L4 preference_rules 应有对应规则 |
| 消费验证 | 让系统写代码 | 应自动使用4空格缩进（偏好生效） |

### 5.2 操作模板（ProcedureTemplate）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 重复操作 | 多次让系统执行类似任务（如"帮我写个 TODO"） | — |
| 巩固后 | 触发 consolidation | 应聚类为 ProcedureTemplate |
| 意图匹配 | 再次说类似意图 | IntentMatcher 应命中模板 |

## 六、项目隔离

### 6.1 隔离项目写入不污染主账户

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 创建隔离项目 | 通过 API 创建 ISOLATED 项目 | — |
| 项目内教学 | 在项目会话中："这个项目用 Python 3.12" | 写入项目 space |
| 主账户验证 | 在非项目会话问 "我用什么语言" | 不应回答 Python 3.12（项目记忆不污染主账户） |

### 6.2 隔离项目继承读取

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 项目内问主账户信息 | 在项目会话问 "我叫什么名字" | 应能读到主账户的姓名（继承读取） |

### 6.3 Overlay 语义

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 项目内更新继承实体 | 在项目会话中："在这个项目里我用 Java 17" | 应创建 overlay，不修改主账户 |
| 项目内验证 | 项目会话问 "我用什么 Java 版本" | 回答 Java 17（overlay 优先） |
| 主账户验证 | 非项目会话问同样问题 | 回答主账户的版本（不受 overlay 影响） |

---

## 七、巩固管线（ConsolidationPipeline）

### 7.1 语义巩固（高频实体 importance 提升）

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 多次提及 | 在多个会话中反复提到"咪咪" | — |
| 触发巩固 | 等待 cron 或手动触发 | "咪咪"实体的 importanceScore 应提升 |

### 7.2 用户画像巩固

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 教学多项信息 | 姓名、职业、城市、爱好等 | — |
| 触发巩固 | 对话完成后异步触发 | `__consolidated_profile` 实体应包含所有碎片的综合画像 |
| 热记忆验证 | 新会话问 "你了解我多少" | 应返回综合画像而非碎片列表 |

### 7.3 经验合并

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 产生相似经验 | 多次执行类似任务并成功 | 产生多条 EXPERIENCE 实体 |
| 触发巩固 | — | 相似经验应合并为泛化元经验 |

---

## 八、遗忘引擎（ForgettingEngine）

### 8.1 低频实体遗忘

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 写入低重要度实体 | "今天天气不错"（低 importance） | — |
| 触发遗忘 | 等待 cron 或手动触发 | 低频低重要度实体应被归档 |
| 验证归档 | memory.search 该实体 | 不再返回（ARCHIVED 不可召回） |

### 8.2 保护机制

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 高频实体 | 多次访问某实体（accessCount ≥ 10） | — |
| 触发遗忘 | — | 高频实体不应被遗忘 |
| 受保护类型 | PREFERENCE / HABIT / GOAL 类型 | 即使低频也不应被遗忘 |

## 九、反馈闭环

### 9.1 正反馈提升

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 点赞回答 | 对使用了某记忆的回答点赞 | 相关实体 trust_score 应提升 |

### 9.2 负反馈降权

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 点踩回答 | 对使用了错误记忆的回答点踩 | 相关实体 trust_score 应下降 |
| 累计负反馈 | 多次点踩同一实体相关回答 | 达到阈值后实体应被 SUPERSEDED |

## 十、数据质量治理

### 10.1 evidence_kind 正确标注

| 来源 | 期望 evidence_kind |
|------|-------------------|
| 用户直接陈述 "我叫李华" | USER_EXPLICIT |
| 用户通过 UI 创建 | USER_CONFIRMED |
| 从对话推断 "他可能喜欢..." | CHAT_INFERRED |
| 工具验证的事实 | TOOL_VERIFIED |
| 巩固/合并产生 | DERIVED |

### 10.2 trust_level 消费规则

| trust_level | 是否自动注入 Prompt | 是否可搜索 |
|-------------|-------------------|-----------|
| VERIFIED | 是 | 是 |
| EXPLICIT | 是 | 是 |
| INFERRED | 仅强相关时，标注"推断" | 是 |
| DERIVED | 是，标注派生 | 是 |
| UNVERIFIED | 否 | 否 |

---

## 十一、向量投影与检索

### 11.1 Projection Outbox

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 写入实体 | 创建新实体 | outbox 应有 PENDING → PROCESSED 记录 |
| 归档实体 | 归档某实体 | outbox 应有 DELETE 投影任务 |
| 向量可搜 | 写入后搜索 | 向量路径应能命中 |

### 11.2 三路融合（HybridRetriever）

| 路径 | 验证方式 |
|------|---------|
| 向量 | 语义相似查询能命中（如"宠物"命中"咪咪"） |
| FTS | 精确关键词能命中（如"咪咪"直接命中） |
| 图遍历 | 有关系边的实体能通过图扩展命中 |

---

## 执行策略

1. **场景 1-4**：通过对话接口逐步执行，每步验证
2. **场景 5-6**：需要项目 API 配合
3. **场景 7-8**：需要手动触发巩固/遗忘（或等待 cron）
4. **场景 9**：需要反馈 API
5. **场景 10-11**：通过搜索结果的字段验证

优先级：1-4 > 5-6 > 10-11 > 7-8 > 9

---

## 通过标准

| 级别 | 标准 |
|------|------|
| P0 必过 | 场景 1-4 全部通过（写入、更新、合并、消费） |
| P1 应过 | 场景 5-6 通过（冷召回、项目隔离） |
| P2 期望 | 场景 7-11 通过（巩固、遗忘、反馈、质量、向量） |
