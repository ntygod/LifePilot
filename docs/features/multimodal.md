# 多模态能力

> 本文档从 [FEATURES.md](../FEATURES.md) 拆分而来，对应 ROADMAP.md §3.4 章节。

> ⚠️ 本文档描述的是目标功能设计，尚未实现。

支持图片理解、视频理解、文档解析、语音输入（STT）和语音输出（TTS），扩展 LifePilot 从纯文本交互到多模态交互。

## 1. 图片理解

### 1.1 支持的场景

| 场景 | 描述 | 示例 |
|------|------|------|
| 截图分析 | 理解屏幕截图中的内容 | "这个报错截图是什么意思？" |
| 照片识别 | 识别照片中的物体、文字、场景 | "这张照片里的菜单有哪些菜？" |
| 图表解读 | 解读图表、流程图中的数据和关系 | "这个柱状图的趋势是什么？" |
| 文档扫描 | 识别扫描件/照片中的文字 | "帮我提取这张名片上的信息" |
| 多图对比 | 同时分析多张图片 | "这两张图有什么区别？" |

### 1.2 支持的图片格式

PNG、JPEG、GIF、WebP、BMP。单张图片最大 10MB，单次请求最多 5 张图片。超大图片自动压缩缩放。

### 1.3 视觉模型

| 模型 | 类型 | 特点 |
|------|------|------|
| LLaVA / Llama3.2-vision / MiniCPM-V | Ollama 本地 | 数据不出本机，零成本，适合隐私敏感场景 |
| Qwen-VL-Plus / Qwen-VL-Max | 通义千问云端 | 视觉理解能力强，中文支持好 |
| GLM-4V | 智谱云端 | 国产多模态模型，合规性好 |

路由策略：本地视觉模型优先，不可用时自动故障转移到云端视觉模型。不支持视觉的模型（如 DeepSeek）不参与多模态路由。

## 2. 视频理解

### 2.1 支持的场景

| 场景 | 描述 | 示例 |
|------|------|------|
| 视频摘要 | 理解视频内容并生成文字摘要 | "帮我总结这个教程视频的要点" |
| 会议回放 | 分析会议录像，提取关键信息 | "这段会议视频讨论了哪些决策？" |
| 教程分析 | 理解操作演示视频 | "这个视频里演示了什么操作步骤？" |
| 视频问答 | 针对视频内容进行问答 | "视频里第 3 分钟出现了什么？" |

### 2.2 支持的视频格式

MP4、AVI、MOV、MKV、WebM、FLV。单个视频文件最大 500MB，最长 30 分钟。

### 2.3 处理策略

采用"分治"策略（借鉴 [OmAgent](https://arxiv.org/abs/2406.16620) 视频理解框架）：

1. **关键帧提取**：按视频时长自适应采样间隔，提取代表性帧（短视频每 2 秒 1 帧，长视频每 15-30 秒 1 帧）
2. **音轨分离**：提取视频音轨，通过 AudioTranscriber 转录为文字
3. **合并理解**：将关键帧（图片）+ 转录文本作为上下文传给视觉模型

```
视频文件 → 关键帧提取 → 图片预处理 → 视觉模型理解
         → 音轨分离   → STT 转录   → 文本上下文
                                     ↓
                              合并为结构化上下文 → LLM 回答
```

### 2.4 视频理解模型

| 模型 | 类型 | 特点 |
|------|------|------|
| Qwen2.5-VL | Ollama 本地 | 支持 20 分钟以上视频理解，本地部署零成本 |
| Qwen-VL-Max | 通义千问云端 | 原生视频理解，精度高 |
| GPT-4o | OpenAI 云端 | 通过关键帧序列理解视频 |

### 2.5 技术实现

视频处理基于 JavaCV（FFmpeg Java 绑定），内嵌各平台 native library，无需用户安装 FFmpeg。

## 3. 文档解析

### 3.1 支持的格式

| 格式 | 解析方式 | 提取内容 |
|------|---------|---------|
| PDF | Apache PDFBox（已有） | 文本、表格结构 |
| Word（.docx/.doc） | Apache POI（已有） | 文本、标题层次 |
| Markdown | CommonMark（已有） | 纯文本 |
| TXT | 直接读取 | 纯文本 |

文档解析复用知识库模块已有的解析器（`PdfParser`、`WordParser`、`MarkdownParser`、`PlainTextParser`），不重复实现。

### 3.2 使用方式

用户发送文档附件时，系统自动检测格式并提取文本内容，将提取的文本作为上下文传递给 LLM 进行分析。

## 4. 图片预处理

发送给 LLM 前，图片经过自动预处理：

1. **格式检测**：使用 Apache Tika 检测实际 MIME 类型（防止扩展名伪造）
2. **大小校验**：超过限制的图片拒绝处理
3. **尺寸压缩**：超过 2048px 的图片等比缩放（与 OpenAI Tile Token 计算模型对齐）
4. **质量压缩**：JPEG 质量压缩至 85%
5. **格式转换**：统一转为 PNG 或 JPEG

预处理参数可通过 `application.yml` 配置调整。

## 5. 语音输入（STT — 语音转文字）

### 5.1 使用场景

| 场景 | 描述 | 示例 |
|------|------|------|
| 语音指令 | 通过语音消息与 Agent 交互 | 发送语音"帮我查一下明天的日程" |
| 会议录音 | 上传录音文件获取文字摘要 | "帮我总结这段会议录音的要点" |
| 语音笔记 | 快速记录想法 | 发送语音"记一下：下周三要交报告" |

### 5.2 支持的音频格式

WAV、MP3、OGG、M4A、FLAC、WebM。单个音频文件最大 25MB，最长 5 分钟。

### 5.3 转录策略

采用"本地优先"级联降级策略（借鉴 [OpenClaw](https://github.com/openclaw/openclaw) 的音频处理架构）：

1. **本地 Whisper CLI**（优先）：用户自行安装 whisper.cpp，LifePilot 自动检测 PATH。零成本、完全隐私
2. **云端 STT Provider**（降级）：OpenAI Whisper API（`whisper-1` / `gpt-4o-transcribe`），精度更高但需要 API Key

### 5.4 处理流程

语音消息在进入 Agent 引擎前自动转录为文本（"转录前置"模式）：

```
用户语音消息 → AudioTranscriber（STT）→ 文本消息 → AgentLoop → 正常文本处理
```

Agent 引擎无需感知音频模态，转录后的文本与手动输入的文本处理流程完全一致。

## 6. 语音输出（TTS — 文字转语音）

### 6.1 使用场景

| 场景 | 描述 | 示例 |
|------|------|------|
| 语音播报 | Agent 回复以语音形式播放 | 早间日程播报、待办提醒 |
| 无障碍交互 | 视觉不便时通过语音获取信息 | 语音朗读文档摘要 |
| 免提模式 | 驾车/运动时通过语音交互 | 语音问答 |

### 6.2 TTS Provider

基于 Spring AI 的 `TextToSpeechModel` 接口，支持：
- OpenAI TTS（`gpt-4o-mini-tts`）：多种语音风格（alloy / echo / fable / onyx / nova / shimmer）
- 可通过 Spring Boot 配置切换 Provider（如 ElevenLabs）

### 6.3 处理流程

TTS 作为可选的输出后处理，在 Agent 回复文本后转为语音：

```
Agent 文本回复 → SpeechSynthesizer（TTS，可选）→ 音频流 → Channel 输出
```

TTS 是否启用由 Channel 适配器或用户偏好决定（如 CLI 默认不启用，语音消息回复默认启用）。

## 7. 交互方式

### 7.1 CLI

CLI 交互层支持通过文件路径发送图片、视频和音频：

```
> 分析这张图片 /path/to/screenshot.png
> 分析这个视频 /path/to/meeting.mp4
> 转录这段录音 /path/to/meeting.mp3
```

### 7.2 Gateway / Web UI

Gateway 和 Web UI 通过 multipart 请求上传图片/视频/音频/文档附件，与文本消息一起发送。

### 7.3 Channel 适配器

企微/钉钉/飞书等 Channel 适配器自动处理平台的语音消息格式，下载音频文件后交给 `AudioTranscriber` 转录。

## 8. 限制与降级

- 多模态请求仅路由到支持 VISION 能力的 Provider
- 所有视觉模型不可用时，明确告知用户"当前无可用视觉模型"，不静默降级为纯文本
- 本地 Ollama 视觉模型需要用户自行拉取（如 `ollama pull llava`）
- 本地 Whisper CLI 需要用户自行安装（如 `brew install whisper-cpp`）
- STT 所有 Provider 不可用时，提示用户"当前无可用语音转录服务"
- TTS 不可用时，回退为纯文本回复（静默降级，不影响核心功能）
- 图片内容不经过语义缓存（每次请求独立处理）
- 视频文件最大 500MB，最长 30 分钟，超出限制拒绝处理
- 视频处理依赖 JavaCV（内嵌 FFmpeg native library），首次使用需下载约 200MB 依赖
- 视频理解基于关键帧提取 + 音轨 STT 的分治策略，非原生视频输入
