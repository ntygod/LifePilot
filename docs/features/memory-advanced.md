# 记忆系统进阶

> 本文档描述模块 23「记忆系统进阶」的功能特性。
> 基于 Phase 2 已完成的四层认知记忆架构（L1-L3），补全记忆生命周期管理能力。

## 1. 功能概述

记忆系统进阶为 ZhiWei 补全三项核心能力：

1. **L4 程序记忆**：Agent 从重复的成功操作中自动学习「怎么做」，形成可复用的操作模板
2. **记忆巩固管线**：模拟人类睡眠期间的记忆巩固过程，将短期情景记忆提炼为长期知识
3. **智能遗忘引擎**：基于 MaRS 认知遗忘框架，在预算约束下智能清理低价值记忆

这三项能力共同实现了记忆的完整生命周期：形成→巩固→遗忘，让 Agent 的记忆系统像人类大脑一样持续演化。

## 2. 核心特性

### 2.1 L4 程序记忆 — 让 Agent 记住「怎么做」

**用户价值**：Agent 不再每次都从头推理，而是复用之前成功的操作模式，响应更快、结果更一致。

**三类程序知识**：

| 类型 | 说明 | 示例 |
|------|------|------|
| 操作模板 | 多步操作的可复用序列 | "创建会议"：查日历→创建日程→发邀请→设提醒 |
| 偏好规则 | 从用户行为中学习的个人偏好 | "用户偏好上午处理重要邮件"、"习惯用 Markdown 记笔记" |
| 策略模式 | 特定情境下的决策策略 | "当用户说'帮我安排一下'时，优先查日历再创建待办" |

**使用场景**：

```
第一次：用户说"帮我安排明天和张总的会议"
  → Agent 从头推理：查日历 → 创建日程 → 发邀请 → 设提醒（4 步 LLM 推理）

第二次：用户说"帮我安排下周和李总的会议"
  → Agent 从头推理（类似模式）

巩固管线发现两次相似的成功执行 → 提炼为"创建会议"操作模板

第三次：用户说"帮我安排周五和王总的会议"
  → Agent 匹配到"创建会议"模板 → 直接按模板执行，只需填充变量
  → 响应更快，步骤更一致
```

**模板可靠性**：只有成功率 ≥ 70% 且使用次数 ≥ 2 的模板才会被自动推荐。低成功率模板自动淘汰。

### 2.2 记忆巩固管线 — 模拟睡眠期间的记忆整理

**用户价值**：Agent 自动从日常对话中提炼重要知识，无需用户手动整理。频繁提到的人物、事件会被自动强化记忆。

**两个方向的巩固**：

**情景→语义巩固**：
- 分析最近 7 天的对话
- 统计实体提及频率（如"张总"在 5 次对话中被提到）
- 高频实体自动提升重要度评分
- 未被识别的新实体触发知识提取

```
最近 7 天对话分析：
  "张总" 出现 5 次 → importanceScore 提升 0.3
  "XX项目" 出现 4 次 → importanceScore 提升 0.2
  新发现 "李总" 在 3 次对话中出现 → 触发知识提取，创建新实体
```

**情景→程序巩固**：
- 识别成功的多步执行轨迹
- 向量聚类发现重复模式
- 自动提炼为操作模板

```
发现 2 次相似的"安排会议"执行轨迹：
  轨迹 1: 查日历 → 创建日程(团队周会) → 发邀请(张总)
  轨迹 2: 查日历 → 创建日程(项目评审) → 发邀请(李总) → 设提醒
  
  → 提炼模板: "创建会议"
    步骤: 查日历 → 创建日程(${title}) → 发邀请(${participant}) → 设提醒(可选)
    变量: title, participant, time
```

**执行时间**：每日凌晨 3:00 自动执行，不影响日常使用。

### 2.3 智能遗忘引擎 — 让记忆保持精炼

**用户价值**：Agent 不会因为记忆膨胀而变慢或检索质量下降。低价值信息自动清理，重要信息永久保留。

**四阶段渐进遗忘**（MaRS Hybrid 策略）：

| 阶段 | 策略 | 效果 |
|------|------|------|
| 1. FIFO | 超过 365 天的实体直接归档 | 清理过期信息 |
| 2. LRU | 90 天未被访问且从未被检索的实体归档 | 清理无用信息 |
| 3. Priority Decay | 重要度随时间衰减，低于阈值的实体归档 | 渐进淡化 |
| 4. Reflection-Summary | 中等重要度实体压缩为摘要 | 保留核心，释放空间 |

**安全保障**：
- 用户标记为重要的记忆永不遗忘
- 用户偏好、习惯、目标等认知类实体享有更高保留优先级
- 每次遗忘有预算限制，不会一次清理过多
- 所有遗忘操作可审计、可追溯

**执行时间**：每周日凌晨 4:00 自动执行（在巩固管线之后）。

## 3. 配置项

所有参数均可通过 `application.yml` 调整：

### 3.1 L4 程序记忆

| 配置项 | 默认值 | 说明 |
|-------|--------|------|
| `lifepilot.memory.procedural.max-templates` | 200 | 最大模板保留数量 |
| `lifepilot.memory.procedural.min-reliability` | 0.7 | 最低可靠性阈值 |
| `lifepilot.memory.procedural.stale-days` | 90 | 过时天数阈值 |
| `lifepilot.memory.procedural.match-threshold` | 0.6 | 意图匹配最低分数 |

### 3.2 巩固管线

| 配置项 | 默认值 | 说明 |
|-------|--------|------|
| `lifepilot.memory.consolidation.cron` | `0 0 3 * * *` | 巩固执行时间 |
| `lifepilot.memory.consolidation.lookback-days` | 7 | 回溯分析天数 |
| `lifepilot.memory.consolidation.high-frequency-threshold` | 3 | 高频实体阈值 |
| `lifepilot.memory.consolidation.cluster-similarity-threshold` | 0.85 | 聚类相似度阈值 |

### 3.3 遗忘引擎

| 配置项 | 默认值 | 说明 |
|-------|--------|------|
| `lifepilot.memory.forgetting.cron` | `0 0 4 * * SUN` | 遗忘执行时间 |
| `lifepilot.memory.forgetting.max-retention-days` | 365 | 最大保留天数 |
| `lifepilot.memory.forgetting.lru-threshold-days` | 90 | LRU 淘汰天数 |
| `lifepilot.memory.forgetting.max-forget-per-run` | 100 | 单次最大遗忘数 |

## 4. 限制与未来扩展

### 4.1 当前限制

- 巩固管线依赖 LLM 调用（模板提炼、摘要生成），LLM 不可用时巩固和遗忘的 Reflection-Summary 阶段会跳过
- 程序记忆的模板匹配基于意图向量相似度，对语义差异较大但操作相同的场景可能匹配不到
- 遗忘引擎目前仅作用于 L3 语义记忆层，L2 情景记忆的遗忘通过渐进压缩（CompressionService）实现

### 4.2 未来扩展方向

- **Idle-Driven 巩固**：在 Agent 空闲时自动触发巩固，而非仅依赖定时调度（接口已预留）
- **Agentic GraphRAG**：当实体规模超过 50K 时，评估引入图检索 Skill 替代 SQL CTE 遍历
- **跨会话模板演化**：模板根据用户反馈自动调整步骤顺序和参数默认值
- **记忆巩固可视化**：在 Web UI 中展示巩固和遗忘的统计信息
