# 文档/知识库管理

> 本文档从 [FEATURES.md](../FEATURES.md) 拆分而来，对应原文 §2.10 章节。

> ⚠️ 本文档描述的是目标功能设计，尚未实现。

支持多知识库管理，让 ZhiWei 能够理解和检索你的个人文档，与四层认知记忆系统深度融合。

## 1. 核心能力

| 能力 | 说明 |
|------|------|
| 多知识库 | 每个知识库独立配置 Embedding 模型和 Reranker |
| 文档上传 | 支持 PDF、Word、Markdown、TXT 格式 |
| 智能分块 | Fixed / Recursive / Heading 三种分块策略 |
| 混合检索 | 向量相似度 + FTS5 全文 + 可选 Reranker 精排 |
| 记忆融合 | 文档知识与认知记忆四层体系互通 |

## 2. 分块策略

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| Fixed | 通用文档 | 按固定字符数分块，简单高效 |
| Recursive | 长文档 | 递归拆分，保持语义完整性 |
| Heading | 结构化文档 | 按标题层级分块，保留文档结构 |

## 3. 与认知记忆系统的融合

这是 ZhiWei 区别于普通 RAG 系统的关键：

```
┌──────────────────────────────────────────────────┐
│              统一检索层                             │
│         (HybridRetriever)                         │
├──────────────┬──────────────┬────────────────────┤
│  认知记忆检索  │  知识库检索    │  图遍历检索        │
│  (四层记忆)   │  (文档分块)    │  (知识图谱)        │
├──────────────┴──────────────┴────────────────────┤
│           结果融合排序 + 可选 Reranker              │
└──────────────────────────────────────────────────┘
```

- 检索时同时查询知识图谱和文档知识库，结果融合排序
- 文档中提取的关键实体自动写入知识图谱
- 知识库不是独立的 RAG 模块，而是认知记忆体系的有机扩展

**对话示例：**

```
你：帮我找一下上次和张总讨论的技术方案里提到的架构图

ZhiWei：🔍 正在搜索...
         
         在「工作文档库」中找到相关内容：
         📄 技术方案v2.0.pdf — 第 3.2 节「系统架构设计」
         
         同时在知识图谱中发现：
         💡 张总在 3月5日 的会议中对微服务架构表示认可，
            但建议增加缓存层（来源：会议记录）
         
         需要我打开这份文档吗？
```
