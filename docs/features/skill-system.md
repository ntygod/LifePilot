# Skill 系统 — 特性说明

> **文档性质**：特性说明文档
> **模块归属**：`com.lifepilot.skill`
> **最后更新**：2026-03

## 1. 功能概述

Skill 系统为知微提供程序性知识管理能力，让 Agent 能够按需获取专业领域的指令和工具建议。用户可以通过 Markdown 文件声明自定义 Skill，系统也能通过 LLM 自动检测能力缺口并生成新 Skill。Skill 激活后将指令注入 Agent 上下文，增强 Agent 在特定领域的表现，实现"越用越懂你"的自适应体验。

## 2. 核心特性

### 2.1 四源 Skill 管理

支持四种来源的 Skill 统一管理，每种来源有不同的优先级和生命周期：

- **Builtin**：Java 原生实现，优先级 3，不可被覆盖。包含 Todo、Schedule、Habit、Memory 四个核心 Skill。其中 Todo、Schedule、Habit 实现 `ProactiveSkillProvider` 接口，自动向主动推理引擎贡献信号源和候选提供者
- **UserDefined**：Markdown 声明式，用户在 `~/.zhiwei/skills/` 目录下创建 SKILL.md 文件夹即可注册
- **Marketplace**：从 Skill 市场安装，携带包 ID 和索引源信息
- **AutoGenerated**：LLM 驱动的自扩展，需用户确认后才能激活

优先级：Builtin(3) > UserDefined/Marketplace(2) > AutoGenerated(1)

### 2.2 渐进式发现与按需激活

Agent 通过统一的 `skills` 工具实现两步式 Skill 使用：

1. **发现**：调用 `list_skills` 获取所有已注册 Skill 的摘要列表（ID + 描述）
2. **激活**：调用 `activate_skill` 激活指定 Skill，获取完整指令和建议工具列表

这种设计避免了将所有 Skill 指令一次性加载到上下文中，节省 Token 预算。

### 2.3 语义搜索与关键词降级

Skill 搜索支持双模式：

- **语义搜索**：LLM 可用时，基于 Embedding 向量余弦相似度匹配（阈值 > 0.5）
- **关键词降级**：LLM 不可用时，自动降级为基于 Skill 名称和描述的关键词匹配

### 2.4 Markdown 声明式 Skill 与热加载

用户通过创建文件夹结构定义 Skill：

```
~/.zhiwei/skills/
  └── my-skill/
      ├── SKILL.md          # 主定义文件（YAML Frontmatter + Markdown Body）
      └── references/       # 可选参考文件目录
          └── example.md
```

系统通过 WatchService 监听文件变更，支持实时热加载：
- 新建文件夹自动加载注册
- 修改 SKILL.md 自动重新解析（500ms 防抖）
- 删除文件夹自动注销
- 解析失败时保留上一个有效版本

### 2.5 三重安全验证管线

所有 Skill（尤其是自动生成的）必须通过三阶段验证：

1. **格式验证**：校验 SKILL.md 的 YAML Frontmatter 和 Markdown Body 格式
2. **安全验证**：校验工具白名单、风险等级、预算上限，检测 Prompt 注入
3. **沙箱验证**：在隔离环境中验证 Skill 定义的内部一致性

任一阶段失败即终止，拒绝注册。

### 2.6 LLM 驱动的 Skill 自扩展

当用户请求超出现有 Skill 能力范围时，系统自动触发自扩展流程：

1. **缺口检测**：SkillGapDetector 分析用户请求，语义搜索无匹配时使用 LLM 分析缺口
2. **Skill 生成**：SkillGenerator 构建 Prompt（含安全约束和已有 Skill 示例），调用 LLM 生成 SKILL.md
3. **三重验证**：生成的 Skill 必须通过完整验证管线
4. **用户确认**：AutoGenerated Skill 默认 `userConfirmed=false`，必须用户确认后才能激活
5. **持久化**：确认后写入 `~/.zhiwei/skills/auto/{skill-id}/SKILL.md` 并注册

### 2.7 审计追溯

所有 Skill 生命周期事件（注册、注销、激活）自动记录到 SQLite `skill_audit_logs` 表，支持按 Skill ID 和时间范围查询。审计写入异步执行，不阻塞主流程。

## 3. 使用场景

**场景一：Agent 按需激活专业 Skill**

用户请求"帮我规划明天的日程"，Agent 调用 `skills` 工具的 `list_skills` 发现 `schedule` Skill，随后调用 `activate_skill` 激活它，获取日程管理的专业指令和 `schedule.add`、`schedule.list` 等建议工具，从而精准完成日程规划任务。

**场景二：用户自定义领域 Skill**

用户在 `~/.zhiwei/skills/code-review/SKILL.md` 中编写代码审查 Skill，定义审查规则和建议工具。保存后系统自动热加载注册，Agent 在后续对话中即可发现和激活该 Skill。

**场景三：系统自动生成缺失 Skill**

用户请求"帮我分析这份财务报表"，系统检测到没有匹配的 Skill，SkillGapDetector 识别缺口后 SkillGenerator 自动生成财务分析 Skill。经三重验证通过后提示用户确认，确认后 Skill 持久化并可在后续对话中使用。

## 4. 配置项

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `lifepilot.skills.enabled` | `true` | Skill 系统总开关 |
| `lifepilot.skills.directory` | `~/.zhiwei/skills` | Skill 文件目录 |
| `lifepilot.skills.hot-reload-debounce-ms` | `500` | 热加载防抖间隔（毫秒） |
| `lifepilot.skills.skill-filename` | `SKILL.md` | Skill 定义文件名 |
| `lifepilot.skills.search.default-top-k` | `10` | 搜索默认返回数量 |
| `lifepilot.skills.auto-generation.enabled` | `true` | 自扩展功能开关 |
| `lifepilot.skills.auto-generation.gap-threshold` | `0.6` | 缺口检测阈值 |
| `lifepilot.skills.validation.max-instructions-length` | `10000` | 指令最大长度 |
| `lifepilot.skills.builtin.todo.enabled` | `true` | Todo Skill 启用开关 |
| `lifepilot.skills.builtin.schedule.enabled` | `true` | Schedule Skill 启用开关 |
| `lifepilot.skills.builtin.habit.enabled` | `true` | Habit Skill 启用开关 |

## 5. 限制与未来方向

**当前限制**：
- 语义搜索依赖 LLM Embedding 服务，离线时降级为关键词匹配，精度下降
- 自动生成的 Skill 质量受 LLM 能力限制，复杂领域可能需要人工调整
- Skill 间无依赖关系管理，不支持 Skill 组合或继承
- 热加载仅监听一级子目录，不支持嵌套目录结构

**未来方向**：
- Skill 组合与编排：支持多个 Skill 协同工作
- Skill 版本管理：支持 Skill 的版本迭代和回滚
- 社区 Skill 市场：通过 Marketplace 模块实现 Skill 的发布、发现和安装
- Skill 效果评估：基于激活后的任务完成率评估 Skill 质量
