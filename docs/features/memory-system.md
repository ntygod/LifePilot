# 四层认知记忆系统

> 本文档从 [FEATURES.md](../FEATURES.md) 拆分而来，对应原文 §2.3 章节。

> ⚠️ 本文档描述的是目标功能设计，尚未实现。

ZhiWei 的记忆系统设计为一个受认知科学启发的动态记忆架构，而非简单的"保存对话历史"，包含记忆形成、巩固和遗忘三个阶段。

## 1. 四层架构

```
┌─────────────────────────────────────────────────────────────┐
│  L1: Working Memory（工作记忆）                               │
│  存储位置：JVM 内存                                           │
│  内容：当前会话对话、中间工具结果、临时推理状态                  │
│  特点：即时访问（< 1ms），会话结束即清理                       │
├─────────────────────────────────────────────────────────────┤
│  L2: Episodic Memory（情景记忆）                              │
│  存储位置：SQLite                                             │
│  内容：完整对话记录、工具调用轨迹、决策时间线                   │
│  特点：追加写入不可变，支持时间旅行查询                        │
├─────────────────────────────────────────────────────────────┤
│  L3: Semantic Memory（语义记忆）+ 时序知识图谱                 │
│  存储位置：SQLite + sqlite-vec                                │
│  内容：结构化知识实体、实体关系、属性、时间维度                  │
│  特点：可更新（版本化），支持冲突检测和合并                     │
├─────────────────────────────────────────────────────────────┤
│  L4: Procedural Memory（程序记忆）                            │
│  存储位置：SQLite                                             │
│  内容：操作模板、用户偏好模式、决策策略                        │
│  特点：从情景记忆中自动提炼，随使用演化                        │
└─────────────────────────────────────────────────────────────┘
```

## 2. 四层记忆如何协作

当你发送一条消息时，四层记忆同时工作：

1. **L1 工作记忆**：提供当前会话上下文（"刚才聊了什么"）
2. **L4 程序记忆**：匹配操作模板（"上次类似请求怎么处理的"）
3. **L3 语义记忆**：检索相关知识实体（"张总是谁、XX项目是什么"）
4. **L2 情景记忆**：按需检索历史对话（"上周和张总聊了什么"）

所有检索结果由 ContextAssembler 智能组装，按 Agent 当前阶段动态分配 Token 预算。

## 3. 时序知识图谱

传统知识图谱只存储"当前状态"，但现实中信息会随时间变化。ZhiWei 的知识图谱设计中，每个实体和关系都将带有时间维度：

**知识实体类型：**

| 类型 | 说明 | 示例 |
|------|------|------|
| 人物 | 你提到的人 | "张总 — XX科技 CTO，负责采购" |
| 地点 | 常去的地方 | "星巴克中关村店 — 常去的咖啡厅" |
| 事件 | 重要事件 | "2026年Q1项目评审 — 周二完成" |
| 偏好 | 个人喜好 | "不吃香菜，喜欢辣，偏好简洁风格" |
| 习惯 | 日常习惯 | "每天早上7点跑步，周五下午写周报" |
| 目标 | 长期目标 | "今年学会 Rust，Q2 完成产品上线" |
| 项目 | 工作项目 | "XX项目 — 与张总合作，Q1交付" |

**版本化更新**：新信息与旧信息冲突时以最新为准，历史版本保留可查。

```
你：张总最近升职了，现在是VP了

ZhiWei：已更新知识图谱：
         张总的职位：CTO → VP（2026-03-15 更新）
         历史记录已保留，你可以随时查看变更历史。
```

**时间旅行查询**：

```
你：去年这个时候张总是什么职位？

ZhiWei：根据知识图谱记录，2025年3月时张总的职位是 CTO。
         他在 2026年3月15日 升任 VP。
```

## 4. 记忆巩固与遗忘

受认知科学启发，ZhiWei 将实现记忆巩固和遗忘机制：

**记忆巩固**：频繁访问的情景记忆会被提炼为语义记忆（知识实体），成功的操作模式会被提炼为程序记忆（操作模板）。

**智能遗忘**：不是简单地删除旧数据，而是采用分层遗忘策略：
- **重要记忆**：永久保留（用户标记的重要事项、关键决策）
- **普通记忆**：渐进压缩（完整对话 → 摘要 → 要点 → 归档）
- **低价值记忆**：自动清理（重复的日常问候、已完成的临时任务）

> 这确保了 ZhiWei 不会因为数据膨胀而变慢，同时保留了真正重要的信息。

## 5. 混合检索引擎

单一检索方式各有盲区。ZhiWei 将采用三路混合检索：

```
用户查询："张总那个项目进展怎么样了？"
    │
    ├── 路径 A: 向量语义检索（sqlite-vec）
    │   "张总" + "项目" + "进展" → 语义相似度匹配
    │   结果：[张总(0.91), XX项目(0.87), Q1评审(0.72)]
    │
    ├── 路径 B: 全文搜索（SQLite FTS5 + BM25）
    │   精确关键词匹配
    │   结果：[张总, XX项目]
    │
    └── 路径 C: 图遍历检索
        从"张总"出发，沿关系边扩展：
        张总 → 负责 → XX项目 → 里程碑 → Q1评审
        结果：[XX项目, Q1评审, 需求文档v2.0]
              │
              ▼
         合并 + 去重 + 加权排序 → 最终结果
```

三路检索的结果经过加权融合排序，确保既能找到语义相关的内容，也不会遗漏精确匹配的结果，还能发现通过关系链接的间接相关信息。
