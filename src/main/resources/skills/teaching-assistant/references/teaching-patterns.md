# 教学路径决策

5 条路径按判据分流。

## 1. "X 是什么"（首次接触）

判据：只问名词定义，没问"为什么"或"原理"。
→ 定义 → 类比 → 核心要点 → 简短示例 → 点 1-2 个高频误区。
错例：用户问"什么是 X"就丢一堆机制细节。

## 2. "为什么 / 怎么理解"（深入原理）

判据：已知是什么，要机制/设计动机/与近邻概念差别。
→ 类比 → 拆解机制 → 对比相近概念（X vs Y 关键差异）。
硬约束：对比必须说清"什么场景选 X / 什么场景选 Y"，不能只罗列差异。

## 3. "举个例子 / 跑一下"（代码演示）

判据：要可运行、看得到输出的示例。
→ code 跑最小可运行代码 → print 可见输出 → 讲解关键行。
硬约束：必须用 code 跑，不贴静态代码。

## 4. "出几道题 / 我做做"（练习）

判据：想自己动手验证理解。
→ 基础（改参数）×1-2 → 进阶（组合概念）×1-2 → 挑战（半实际问题）×1。
做对点巧思，做错引导分析（不问"你错在哪"→问"输出和你预期差在哪"），不直接给答案。

## 5. "学习路径 / 从零学 X"（规划）

判据：要阶段性 roadmap。
→ 3 句问完水平/目标/偏好 → 入门→进阶→实战分阶段，每段列里程碑。
按用户已有基础裁掉重复，不照搬通用教程目录。

## 概念讲解结构

```
<概念名>
├── 一句话定义（≤30 字）
├── 类比（贴生活）
├── 核心要点（3-5 条要害）
├── 示例（最小可运行）
└── 高频误区（1-2 个）
```

## 练习梯度

| 阶段 | 内容 | 卡住时的引导 |
|------|------|-------------|
| 基础 | 改示例参数看输出变化 | "输出和你预期差在哪" |
| 进阶 | 用 A 概念实现 B 场景 | "A 和 B 的接口是怎么对上的" |
| 挑战 | 半真实需求自由实现 | "分几步做，第一步验证什么" |

## 常见错误

- code 报错 → 贴错误信息，引导读栈帧；卡住 >1 轮才直接指出
- 用户没听懂 → 换完全不同领域的类比，不把同一类比说更长
- 缺前置概念 → 先问"要不要先把 X 补上"，不硬讲
- 进度冲突 → 用户说"我学过 X"但 memory 没记 → 信用户，更新进度
- 练习卡住 → 分层放线索：思路框架 → 伪代码 → 关键片段，每层问一下
