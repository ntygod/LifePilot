# 信息调研指南

用于判断一个问题是否需要联网、多源核查或结构化研究。核心约束：结论必须能追溯到来源；来源冲突时说明分歧和置信度，不把搜索摘要当事实。

## 触发判断
- 技术选型（框架对比、方案评估）
- 竞品分析 / 市场调研
- 行业动态 / 趋势追踪
- 事实核查（"X 是真的吗 / 数据准吗"）
- 学术文献 / 技术文档检索
- 跨多个来源的对比分析

不要触发：

- 已知答案的简单问题 → 直接回答
- 代码库内搜索 → code-assistant
- 数据集统计 → data-analyst
- 已绑定知识库的精确查询 → 直接 `memory`

## 决策路径

| 调研深度 | 用户表达 | 路径 |
|---|---|---|
| **快速答** | "X 是什么 / 听说 X 是真的吗" | 单轮搜索即可，带来源直接答 |
| **深度对比** | "X 和 Y 比 / 选 X 还是 Y / 主流方案有哪些" | 先广度扫描，再抓高价值来源正文 |
| **趋势 / 动态** | "X 最近怎么样 / 行业现在什么趋势" | 明确时间范围，多源汇总 |
| **事实核查** | "这个数字对吗 / X 真的做了 Y 吗" | 至少 2 个独立来源验证，矛盾明示 |

决策要点：

- **先判是否需要联网**：稳定常识、用户本地资料、代码库内事实不走调研流程。
- **先广后深**：搜索用于发现候选来源；关键结论必须读取正文或权威页面。
- **来源分层**：官方文档、论文、法规、公司公告优先；二手文章只作线索。
- **交叉验证**：数字、排名、报价、近期事件至少 2 个独立来源；找不到就说证据不足。
- **结构化输出**：按场景选对比表、证据链、时间线或建议矩阵；每条事实带来源。
- **保存条件**：只有长期参考价值或用户要求归档时，才写报告或记忆关键结论。


## 输出标准

- 输出来源列表、交叉验证结论、分歧、置信度和可执行建议。
- 深度调研可生成报告文件，列路径、范围和引用来源。
- 有长期价值的结论只作为记忆候选，等待用户确认。


## 失败策略

- 无法联网、来源不足或来源冲突时说明限制，不强行下结论。
- 高时效问题必须标明检索日期和来源发布时间。
- 发现事实冲突时给出多种说法和判断依据。
