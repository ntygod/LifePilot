# 日常管理指南

用于把个人计划、进度回顾、跨 Skill 协作和周期性报告收束成可执行安排。重点是判断用户是在表达意图、请求规划、调整已有任务，还是需要跨领域串联。

## 触发判断
- 主动规划：当天 / 一周 / 一月做什么、按优先级排
- 调整既有：把任务挪到别的时间、改优先级、删 / 撤一项
- 进度回顾：现在做到哪、昨天/上周完成了什么
- 跨领域协作：一句指令涉及多个专业 Skill（调研→写作、读数据→画图）
- 报告生成：日报 / 周报 / 月报 / 多源信息汇总

不要触发：

- 精确时间表达式（"每天早上 8 点"）→ cron-scheduler
- 单一专业领域任务（只写文章 / 只查数据库 / 只调试 API）→ 直接加载对应 Skill，不绕本 Skill
- 闲谈式表达意图（"我打算 X"）→ memory(action="create") 记一笔，不规划

## 决策路径

| 用户表达 | 路径 |
|---|---|
| 主动规划（今天/本周做什么） | 拆解候选 → 排优先级 → 用户确认 → 写入 |
| 调整既有（挪、改、撤） | 先查已有项 → 明确改动范围 → 改 / 撤 |
| 进度回顾（做到哪、昨天做了啥） | 查 → 汇总，不写入 |
| 跨领域协作（A 然后 B） | 按依赖串行加载相关 Skill |
| 报告生成（日 / 周 / 月报） | 查事实 → 汇总 → 需要长期保存才落盘 |

决策要点：

- **别急着写入**：用户只是表达想法时，先整理候选；只有明确要跟进或确认后才写记忆。
- **先查再改**：调整、撤销、完成任务前必须先查已有实体，避免创建重复项。
- **时间要具体**：提醒或周期计划缺少日期、频率、时区时先追问。
- **跨 Skill 要少而准**：一次最多加载 3 个 Skill，按依赖串行，前序只传必要产出。
- **报告要分层**：短回顾直接回复；长期周报/月报或用户要求保存时才写文件。
- **降级策略**：依赖 Skill 不可用时，给出手动计划；外部资料不足时先标注缺口，不补事实。

## 协作原则（仅本 Skill 强调）

- 决策节点向用户问，不替用户拍板
- 信息缺失时主动追问，不假设
- 跨 Skill 协调失败（依赖 Skill 不可用 / 中途出错）→ 降级为手动步骤指导


## 输出标准

- 输出清晰的计划、优先级、下一步动作和可跟进任务。
- 需要记忆时只生成候选事实/偏好，标明依据并等待确认。
- 报告类结果要按时间范围、完成项、风险和后续建议组织。


## 失败策略

- 目标太大时先拆成可执行的下一步。
- 信息不足时追问最少问题，避免过早写任务或记忆。
- 多 Skill 协调失败时说明卡点，并给出可单独推进的路径。
