# 写作路径决策

3 条路径按判据分流。

## 1. 从零创作（"写一份 X / 帮我起草"）

判据：全新成稿，没有原文。
→ 确认 4 要素（类型/受众/篇幅/风格）— **缺一不动笔**
→ 收集素材（同轮并行：web.search + memory + file.read）
→ 长文 >2000 字：出大纲 → 用户确认 → 撰写
→ 短文/用户说"直接写"：跳过确认直接出稿
→ 引用数据必标来源

错例：用户只说"帮我写一篇博客"就动笔。

## 2. 润色改写（"帮我改一下 / 优化表达"）

判据：用户已有原文。
→ 读原文 → 问"要改什么"（改风格/改结构/改语气/仅纠错/全优化）
→ 长文出一段前后对比确认方向 → 全文改
→ 输出变更摘要（改了什么/在哪/为什么）

硬约束：**不编造新事实**，不替用户做主张判断。

## 3. 从素材创作（"根据这份笔记/会议记录写一篇"）

判据：用户给了结构化素材。
→ 读素材 → 提取关键信息 → 确认受众/篇幅/风格 → 按格式撰写

## 格式骨架

### 技术文章
```
## 问题 — 一句话说清要解决什么
## 方案 — 怎么做（含代码/命令）
## 要点 — 为什么这样 + 踩坑
```

### 工作报告/周报
```
## 本周完成 — 事项 + 结果
## 下周计划 — 事项 + 预计产出
## 风险/阻塞 — 需要谁协助
```

### 邮件
```
主题：<行动 + 主题>
<称呼>，
<正文：为什么写/核心信息/需要对方做什么>
<署名>
```

## 常见错误

- 素材不够就动笔 → 先搜/先读再写
- 引用不标来源 → 每条数据/观点带来源
- 邮件抄长报告 → 邮件正文尽量 3 段内读完
- 带 ${TOKEN} 原文 → 落盘前检查
