让知微从"即时反应"变成"持续关注"，同时防止过度打扰

④ 意图记忆 — 持久目标追踪

用户说过的目标、愿望、计划，不是聊完就忘——而是持久存储，每次心跳检查触发条件。
这是知微从"问一答一"到"贾维斯式持续关注"的关键能力。
示例：一条意图的生命周期
提取
用户对话中说：
"等那个耳机降到 300 以下我就买"
→
存储
目标: 买耳机
触发: 价格 < 300
过期: 90天
→
触发
第 12 天心跳发现
价格降到 279
→ 主动通知用户
→
完成
用户反馈"有用"
或自主度 C 下
直接代下单
// 意图记录
record Intent(
  String id,
  String userId,
  String goal,           // "买耳机"
  String triggerCondition, // 结构化条件 或 自然语言
  String sourceSessionId, // 从哪次对话提取的
  IntentStatus status,    // ACTIVE / TRIGGERED / FULFILLED / EXPIRED
  LocalDateTime createdAt,
  LocalDateTime expiresAt, // 自动过期，防止永远占着
  int checkCount         // 已检查次数，用于衰减
)
意图从哪来？
• 对话提取 — 从 L2 情景记忆中识别"我想...""帮我盯着...""等...的时候告诉我"
• 用户显式创建 — 对话中直接对知微说"帮我关注 XX"
• 行为插件产出 — 任务代行插件执行后产生后续意图

⑤ 统一决策门控 — 防过度打扰的最后防线

多个插件可能同时产出候选动作。门控负责：选哪个？怎么投递？要不要拦截？
硬边界（一票否决）
• 安静时段（23:00-08:00）
• 同话题冷却期未过
• 每日上限已达
• 用户在全屏/专注模式
软约束（降级处理）
• 已有一条通知未读 → 排队
• 用户刚拒绝过上一条 → 降级为静默
• 多个候选并列 → 只推最高分的
• 信任度不够 → 降一级自主度
自主度检查
• A 通知型 → 只允许通知/排队
• B 建议型 → 允许通知+带方案
• C 代行型 → 允许执行，完成后告知
投递级别决定
• 分数 < 0.3 → 静默（仅记录）
• 分数 0.3-0.5 → 排队到下次对话
• 分数 0.5-0.7 → 浮窗通知气泡
• 分数 ≥ 0.7 → 主动消息/打断
复用现有能力：
• 硬边界检查 → 现有 ReminderDecisionEngine 的逻辑直接上提
• LinUCB 赌博机 → 从提醒专用变成全局共享，所有插件的动作都经过它
• 反馈仓库 → 从提醒专用扩展为全行为类型
• 新增："排队"投递级别（现在没有，动作不是推就是不推）
